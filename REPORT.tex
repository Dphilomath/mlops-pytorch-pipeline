\section{Executive Summary}
This project delivers a complete, production-grade MLOps pipeline for training, containerizing, orchestrating, and serving a CIFAR-10 image classification model. The system integrates:
\begin{itemize}[noitemsep]
    \item \textbf{PyTorch Transfer Learning}: ResNet-18 initialized with ImageNet pre-trained weights and fine-tuned for CIFAR-10.
    \item \textbf{Docker Multi-Stage Builds}: Optimized CPU-only container images with non-root security enforcement and built-in healthchecks.
    \item \textbf{Kubernetes Orchestration}: Dedicated \texttt{ml-training} namespace, persistent volume caching for datasets and checkpoints, batch training \texttt{Job}, declarative \texttt{ConfigMap}s, and autoscaling model serving \texttt{Deployment} with Horizontal Pod Autoscaler (HPA).
    \item \textbf{Production Additions}: Centralized MLflow experiment tracking and model registry, Nginx SSL/TLS Ingress subpath routing, and an interactive glassmorphic Web UI.
\end{itemize}

\section{System Architecture \& Implementation Breakdown}

\subsection{Part A: Repository \& CI/CD Setup}
The codebase adheres strictly to the required directory structure:
\begin{itemize}[noitemsep]
    \item \texttt{src/}: Contains \texttt{model.py}, \texttt{dataset.py}, \texttt{train.py}, and \texttt{serve.py}.
    \item \texttt{configs/}: Declarative YAML configuration files (\texttt{training\_config.yaml}, \texttt{serving\_config.yaml}).
    \item \texttt{docker/}: Multi-stage Dockerfiles (\texttt{Dockerfile.train}, \texttt{Dockerfile.serve}).
    \item \texttt{k8s/}: Kubernetes manifests (\texttt{namespace.yaml}, \texttt{configmap.yaml}, \texttt{training-job.yaml}, \texttt{serving-deployment.yaml}, \texttt{serving-service.yaml}, \texttt{hpa.yaml}, \texttt{ingress.yaml}, \texttt{kustomization.yaml}).
    \item \texttt{.github/workflows/}: CI pipeline running automated linting (\texttt{black}, \texttt{flake8}) and unit testing (\texttt{pytest}).
\end{itemize}

\subsection{Part B: PyTorch Model \& Application}
\begin{itemize}
    \item \textbf{Model Architecture (\texttt{src/model.py})}: Fine-tuned torchvision \texttt{ResNet-18} initialized with ImageNet weights (\texttt{weights="DEFAULT"}), replacing the final fully-connected linear layer with $\text{Linear}(512, 10)$.
    \item \textbf{Data Pipeline (\texttt{src/dataset.py})}: Dataset streaming engine with multi-mirror failover, $64 \times 64$ scaling, ImageNet normalization ($\mu=[0.485, 0.456, 0.406], \sigma=[0.229, 0.224, 0.225]$), and data augmentations (Random Horizontal Flip, 15$^\circ$ Rotation, Color Jitter).
    \item \textbf{Training Loop (\texttt{src/train.py})}: Reads hyperparameters from ConfigMap, logs JSON Lines events to \texttt{stdout}, applies Cosine Annealing learning rate schedule, logs metrics to MLflow, and saves the best model checkpoint to \texttt{/app/checkpoints/classifier\_v1.pt}.
    \item \textbf{Inference Server (\texttt{src/serve.py})}: FastAPI service exposing \texttt{GET /health} and \texttt{POST /predict} returning softmax probabilities for all 10 CIFAR-10 classes.
\end{itemize}

\subsection{Part C: Docker Containerization}
\begin{itemize}
    \item \textbf{Training Image (\texttt{docker/Dockerfile.train})}: Multi-stage build based on \texttt{python:3.11-slim} pulling CPU-only PyTorch wheels.
    \item \textbf{Serving Image (\texttt{docker/Dockerfile.serve})}: Minimal inference runtime, exposes port 8080, enforces non-root execution (\texttt{USER appuser}, \texttt{TORCH\_HOME=/tmp}), and incorporates a native Docker \texttt{HEALTHCHECK}.
\end{itemize}

\subsection{Part D \& E: Kubernetes Orchestration}
\begin{itemize}
    \item \textbf{Namespace}: \texttt{ml-training} labeled with \texttt{project: mlops-pytorch-pipeline}.
    \item \textbf{Storage}: Persistent Volume Claims \texttt{data-pvc} (5Gi) and \texttt{checkpoint-pvc} (2Gi) decouple data and checkpoint lifecycles from ephemeral container restarts.
    \item \textbf{Training Job}: Kubernetes batch \texttt{Job} executing containerized PyTorch training with 4-core parallel CPU allocation and \texttt{TORCH\_NUM\_THREADS=4}.
    \item \textbf{Serving Deployment}: 2 Replicas with \texttt{RollingUpdate} strategy (\texttt{maxSurge: 1, maxUnavailable: 0}), Liveness/Readiness probes against \texttt{/health}, ClusterIP Service exposing port 80 targeting 8080, and HPA scaling up to 3 replicas at 80\% CPU utilization.
\end{itemize}

\section{Major Technical Challenges \& Resolutions}

\begin{enumerate}
    \item \textbf{Docker Image Bloat (8.5 GB $\rightarrow$ 1.4 GB)}: Default PyPI PyTorch Linux wheels bundle full CUDA 12 and cuDNN shared libraries. Resolved by targeting \texttt{--extra-index-url https://download.pytorch.org/whl/cpu} in Dockerfiles, reducing image footprint by 83\%.
    \item \textbf{Dataloader Shared Memory Deadlock \& OOM (Exit 137)}: Multiprocessing workers in containerized environments exceeded \texttt{/dev/shm} and tripled RAM consumption. Resolved by standardizing \texttt{num\_workers=0} for CPU container execution.
    \item \textbf{Non-Root PyTorch Hub Permissions}: Non-root serving containers failed with \texttt{PermissionError: /nonexistent/.cache}. Resolved by configuring \texttt{ENV TORCH\_HOME=/tmp} and instantiating model architecture with \texttt{weights=None} before loading custom checkpoints.
    \item \textbf{MLflow Distributed Artifact Uploads}: Remote client pods could not write to MLflow server disk. Resolved by adding \texttt{--serve-artifacts} to the MLflow tracking server to proxy all artifact streaming over HTTP multipart POST.
    \item \textbf{Inference Image Dimension Mismatch}: High-resolution uploads were causing prediction drift. Unified inference preprocessing in \texttt{src/serve.py} via \texttt{get\_transforms(train=False, strategy="transfer\_learning")} to guarantee $64 \times 64$ resizing and ImageNet normalization.
    \item \textbf{Transition to Transfer Learning}: Scratch training was slow ($>15$ epochs, $<40\%$ accuracy). Leveraging pre-trained ResNet-18 ImageNet weights and Cosine Annealing propelled validation accuracy to \textbf{77.26\% on Epoch 1} and $>85\%$ on subsequent epochs.
\end{enumerate}
